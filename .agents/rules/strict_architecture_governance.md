# Rule: Strict Architecture & Documentation-First Governance

**Enforcement Level:** CRITICAL / MANDATORY

## 1. Strict Adherence to Architecture Documents (`ADR.md`, `SAD.md`, `SDD.md`)

AI Agent และผู้พัฒนาต้องยึดถือโครงสร้างไดเรกทอรี, ชื่อไฟล์, โมดูล, อินเทอร์เฟซ, และลำดับการทำงานตามที่ระบุไว้ในเอกสารทั้ง 3 ฉบับในโฟลเดอร์ `/Docs/` อย่างเคร่งครัด:

- `Docs/ADR.md` (Architectural Decision Records)
- `Docs/SAD.md` (System Architecture Document)
- `Docs/SDD.md` (Software Design Document)

**ห้าม** สร้างไฟล์โค้ดใหม่, เปลี่ยนชื่อไฟล์, ย้ายโฟลเดอร์, หรือเปลี่ยนโครงสร้างสถาปัตยกรรมให้แตกต่างไปจากที่ระบุไว้ใน `Docs/SAD.md` และ `Docs/SDD.md` โดยพลการอย่างเด็ดขาด

---

## 2. Mandatory Change Control Protocol (ขั้นตอนบังคับเมื่อจำเป็นต้องเปลี่ยนแปลงโครงสร้าง)

หากการพัฒนาฟีเจอร์ใหม่หรือการแก้ไขปัญหาในอนาคต **มีความจำเป็นต้องปรับปรุงโครงสร้างไฟล์ ชื่อไฟล์ หรือสถาปัตยกรรมให้แตกต่างไปจากเอกสารปัจจุบัน** AI Agent ต้องปฏิบัติตามลำดับขั้นตอนนี้ **100% โดยห้ามข้ามขั้นตอน**:

1. **STOP & REQUEST PERMISSION (หยุดและขออนุญาตก่อนเสมอ):**
   - ห้ามลงมือเขียนหรือแก้ไขโค้ดที่กระทบโครงสร้างทันที
   - ต้องแจ้งรายละเอียดสิ่งที่ต้องการเปลี่ยนแปลง (เช่น ชื่อไฟล์ที่จะเพิ่ม/ลบ/แก้ไข) พร้อมอธิบายเหตุผลทางเทคนิคให้ผู้ใช้ทราบ และ **รอจนกว่าผู้ใช้จะตอบอนุมัติอย่างชัดเจน**
2. **RECORD IN `Docs/ADR.md` (บันทึกการตัดสินใจลงใน ADR):**
   - เมื่อได้รับอนุมัติจากผู้ใช้แล้ว ให้เพิ่มหัวข้อ `ADR-00X` ใหม่ลงใน `Docs/ADR.md` โดยระบุวันที่, สถานะ, บริบทปัญหา (Context), การตัดสินใจ (Decision), และผลกระทบ (Consequences) ให้ชัดเจน
3. **UPDATE `Docs/SAD.md` & `Docs/SDD.md` (ปรับปรุงเอกสารสถาปัตยกรรมและดีไซน์):**
   - อัปเดตแผนผังโครงสร้างไฟล์ใน `Docs/SAD.md` และรายละเอียดการออกแบบโมดูลใน `Docs/SDD.md` ให้ตรงกับการเปลี่ยนแปลงที่ได้รับอนุมัติ
4. **IMPLEMENT CODE CHANGES (ลงมือแก้ไขโค้ดตามเอกสารใหม่):**
   - เมื่อเอกสาร `ADR.md`, `SAD.md`, และ `SDD.md` ถูกปรับปรุงเรียบร้อยแล้ว จึงจะสามารถเขียนหรือแก้ไขซอร์สโค้ดและระบบให้เป็นไปตามเอกสารที่เปลี่ยนแปลงแล้วได้
